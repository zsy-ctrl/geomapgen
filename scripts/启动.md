# 当前数据集制作与验证启动说明

这份说明对应当前 `geo_current_v1` 的**滑动窗口切 patch**版本。

现在不再使用中心点 family grid 主逻辑，改为：

- `tile_size_px`
- `overlap_px`
- `keep_margin_px`

来切 patch。

### 训练集 + 验证集

```powershell

  --dataset-root "你的数据集根目录" `
```

## 2. 当前数据集制作链

### 第一步：构建 `family_manifest`

入口脚本：

- `scripts/build_geo_current_family_manifest.py`

作用：

- 扫描原始数据集目录
- 读取原始 `tif`、`review mask`、`Lane.geojson`、`Intersection.geojson`
- 先按 `review mask` 限制搜索区域
- 再按滑动窗口切 patch
- 为每个 patch 记录：
  - `crop_box`
  - `keep_box`
  - `mask_ratio`
  - `mask_pixels`

### 第二步：一次性导出 A/B 两阶段训练数据

入口脚本：

- `scripts/export_llamafactory_both_from_geo_current_family_manifest.py`

命令：

```powershell
python scripts/export_llamafactory_both_from_geo_current_family_manifest.py `
  --family-manifest "D:\output\family_manifest.jsonl" `
  --output-root "D:\output\processed" `
  --splits train val `
  --use-system-prompt `
  --resample-step-px 12.0 `
  --boundary-tol-px 2.5 `
  --trace-points 8 `
  --state-mixture-mode full `
  --state-no-state-ratio 0.30 `
  --state-weak-ratio 0.40 `
  --state-full-ratio 0.30 `
  --state-weak-trace-points 3 `
  --state-line-dropout 0.40 `
  --state-point-jitter-px 2.0 `
  --state-truncate-prob 0.30
```

导出后会得到：

- `D:\output\processed\stage_a\dataset`
- `D:\output\processed\stage_b\dataset`

### 第三步：合并多机处理结果

入口脚本：

- `scripts/merge_geo_current_v1_processed_shards.py`

```powershell
python scripts/merge_geo_current_v1_processed_shards.py `
```

## 3. 当前裁剪参数

### patch 组织参数

- `tile_size_px = 896`
  - patch 裁剪大小
- `overlap_px = 232`
  - 相邻 patch 的重叠宽度
- `keep_margin_px = 116`
  - patch 内部真正归当前 patch 所有的保留边距

### mask 与搜索区域参数

- `mask_threshold = 127`
- `review_crop_pad_px = 64`
- `search_within_review_bbox = true`

### 几何参数

- `resample_step_px = 12.0`
- `boundary_tol_px = 2.5`
- `trace_points = 8`

### B 阶段 state 参数

当前为了便于调试，默认关闭 mixed augmentation：

- `state_mixture_mode = full`

## 4. 当前算法要点

### 图像裁剪

- 先读取整张原始 `tif`
- 再读取整张 `review mask`
- 先在整图上应用 mask
- mask 外区域直接置黑
- 再按滑动窗口的 `crop_box` 裁出 patch 图像

### 真值裁剪

- 线和路口先在全局坐标下处理
- 先按 `review mask` 做几何裁切
- 再按 patch 的 `keep_box` 裁切出当前 patch 的监督

### overlap 的使用方式

- patch 图像看整个 `crop_box`
- patch 监督只认 `keep_box`
- `keep_box` 由 `keep_margin_px` 计算得到

### 坐标形式

- `family_manifest` 里的 `crop_box / keep_box / center_x / center_y`
  - 是相对整张大图左上角的全局像素坐标
- `target_lines / state_lines`
  - 是相对当前 patch 左上角的 patch-local 整数像素坐标

### 排序与方向规范

当前保持：

- 单条线方向规范化
- 多条线稳定排序
- 线重采样

## 5. 验证脚本：从已裁剪训练数据回推全尺寸 GeoTIFF / GeoJSON

入口脚本：

- `scripts/reconstruct_geo_current_from_processed_dataset.py`

作用：

- 读取已导出的训练数据集：
  - patch 图片
  - `meta_train.jsonl` / `meta_val.jsonl`
  - `family_manifest.jsonl`
- 回拼一张与原始 tif 同像素大小的 GeoTIFF
- 额外输出一张可视化叠加图：
  - 把线投影到回拼后的图像上
  - 在线的起点和终点标记 `start / cut / end` 等属性
- 同时把 `target_lines` 反投回全局坐标，输出：
  - `Lane.geojson`
  - `IntersectionBoundary.geojson`

### 验证脚本启动命令

```powershell
python scripts/reconstruct_geo_current_from_processed_dataset.py `
  --processed-root "D:\output\processed" `
  --output-root "D:\output\verify_train" `
  --split train `
  --stage stage_a
```

### 只验证某一个原始 sample

```powershell
python scripts/reconstruct_geo_current_from_processed_dataset.py `
  --processed-root "D:\output\processed" `
  --output-root "D:\output\verify_one" `
  --split train `
  --stage stage_a `
  --source-sample-id "你的sample_id"
```

### 输出结果

脚本会输出到：

- `输出目录\sample_id\masked_reconstructed.tif`
- `输出目录\sample_id\masked_reconstructed_overlay.png`
- `输出目录\sample_id\Lane.geojson`
- `输出目录\sample_id\IntersectionBoundary.geojson`
- `输出目录\reconstruct_summary.json`

## 6. 这个验证脚本检查什么

主要检查两件事：

1. 图像裁剪是否正确
   - patch 回拼后是否与 mask 后原图一致
   - patch 位置是否和 `crop_box` 一致

2. 真值裁切是否正确
   - `target_lines` 反投回全局后是否落在正确位置
   - 道路和路口边界是否符合 patch 导出的结果
