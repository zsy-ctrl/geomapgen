# 当前数据集制作与验证说明

这份说明对应当前 `geo_current_v1` 这条数据集制作链。  
这里写的是**现在实际生效**的方式，不再沿用旧的 `tile-size / overlap / keep-margin` 说法。

## 1. 当前数据集制作链

### 第一步：构建 `family_manifest`
入口脚本：

- `scripts/build_geo_current_family_manifest.py`

作用：

- 扫描原始数据集目录
- 读取原始 `tif`、`review mask`、`Lane.geojson`、`Intersection.geojson`
- 按固定中心网格生成 patch family
- 为每个 patch 计算：
  - `crop_box`
  - `keep_box`（ownership rect）
  - `mask_ratio`
  - `mask_pixels`

### 第二步：一次性导出训练数据集
入口脚本：

- `scripts/export_llamafactory_both_from_geo_current_family_manifest.py`

作用：

- 读取上一步生成的 `family_manifest.jsonl`
- 读取原始图像和真值
- 生成：
  - `stage_a/dataset`
  - `stage_b/dataset`
- 输出 patch 图片、`train.jsonl / val.jsonl`、`meta_train.jsonl / meta_val.jsonl`

### 第三步：合并多机处理结果
入口脚本：

- `scripts/merge_geo_current_v1_processed_shards.py`

作用：

- 合并多个分片机器导出的：
  - `family_manifest.jsonl`
  - `stage_a/dataset`
  - `stage_b/dataset`

## 2. 当前裁剪参数

### patch 组织参数

- `crop_size_px = 896`
  - 每个 patch 的裁剪尺寸
- `base_start_px = 448`
  - 搜索区域内第一列 / 第一行中心点相对区域起点的偏移
- `base_stride_px = 664`
  - 相邻 patch 中心点之间的步长
- `axis_count = 5`
  - 每个轴最多取多少个中心点
- `family_grid_size = 4`
  - 每个 family 由 `4 x 4` 个 patch 组成

### mask 与搜索区域参数

- `mask_threshold = 127`
  - `review mask` 二值化阈值
- `review_crop_pad_px = 64`
  - `search_within_review_bbox` 打开时，对 review mask 外接框的扩边像素
- `search_within_review_bbox = true`
  - 先按 review mask 的全局外接框限制 patch 搜索区域

### 几何参数

- `resample_step_px = 12.0`
  - 线裁切后的重采样步长
- `boundary_tol_px = 2.5`
  - 判断线端点是否贴在 patch / ownership 边界上的容差
- `trace_points = 8`
  - B 阶段 state trace 默认保留的点数

### B 阶段 state 参数

当前为了便于调试，**默认关闭 mixed augmentation**：

- `state_mixture_mode = full`

也就是：

- 不做 `no_state / weak_state / full_state` 混合
- 不随机 dropout / jitter / truncate 作为主路

## 3. 当前算法要点

### 3.1 图像裁剪

- 先读取原始整张 `tif`
- 再读取整张 `review mask`
- **先在整图上应用 mask**
  - mask 外区域直接置黑
- 然后再根据 `crop_box` 裁 patch 图像

所以 patch 图片本身已经是：

- 只保留 mask 内真实图像
- 其他位置为 mask 后的空区域

### 3.2 线与路口真值裁剪

- 线和路口边界先在**全局坐标**下处理
- 先按 `review mask` 做几何裁切
- 再按 patch 的归属区域裁切

### 3.3 overlap 的使用方式

当前 overlap 不再用旧的 `keep_margin` 主导，而是用：

- `keep_box = ownership rect`

具体是：

- patch 输入看整个 `crop_box`
- patch 监督只认 `keep_box`
- `keep_box` 由当前 patch 中心和相邻 patch 中心的中线决定

### 3.4 坐标形式

- `family_manifest` 中的 `crop_box / keep_box / center_x / center_y`
  - 都是**相对整张大图左上角的全局像素坐标**
- `target_lines / state_lines`
  - 都是**相对当前 patch 左上角的 patch-local 整数像素坐标**

### 3.5 排序与方向规范

当前保持：

- 单条线方向规范化
- 多条线稳定排序
- 线重采样

这部分沿用 `v1.0` 同类逻辑。

## 4. Windows 下常用启动命令

### 4.1 构建 `family_manifest`

```powershell
python scripts/build_geo_current_family_manifest.py `
  --dataset-root "你的数据集根目录" `
  --output-manifest "D:\output\family_manifest.jsonl" `
  --splits train val `
  --crop-size-px 896 `
  --base-start-px 448 `
  --base-stride-px 664 `
  --axis-count 5 `
  --family-grid-size 4 `
  --review-crop-pad-px 64 `
  --tile-min-mask-ratio 0.02 `
  --tile-min-mask-pixels 256 `
  --search-within-review-bbox `
  --fallback-to-all-if-empty
```

### 4.2 一次性导出 A/B 两阶段训练数据

```powershell
python scripts/export_llamafactory_both_from_geo_current_family_manifest.py `
  --family-manifest "D:\output\family_manifest.jsonl" `
  --output-root "D:\output\processed" `
  --splits train val `
  --use-system-prompt `
  --resample-step-px 12.0 `
  --boundary-tol-px 2.5 `
  --trace-points 8 `
  --state-mixture-mode full `
  --state-no-state-ratio 0.30 `
  --state-weak-ratio 0.40 `
  --state-full-ratio 0.30 `
  --state-weak-trace-points 3 `
  --state-line-dropout 0.40 `
  --state-point-jitter-px 2.0 `
  --state-truncate-prob 0.30
```

导出后你会得到：

- `D:\output\processed\stage_a\dataset`
- `D:\output\processed\stage_b\dataset`

### 4.3 合并多机处理结果

```powershell
python scripts/merge_geo_current_v1_processed_shards.py `
  --output-root "D:\output\merged" `
  --shard-roots "D:\shard0" "D:\shard1" "D:\shard2"
```

## 5. 验证脚本：从已裁剪训练数据反推回全尺寸 GeoTIFF / GeoJSON

入口脚本：

- `scripts/reconstruct_geo_current_from_processed_dataset.py`

作用：

- 读取已导出的训练数据集：
  - patch 图片
  - `meta_train.jsonl` / `meta_val.jsonl`
  - `family_manifest.jsonl`
- 回拼一张**与原始 tif 同像素大小**的 GeoTIFF
- 这张 GeoTIFF 的内容来自数据集中的 patch 图片
- 因为 patch 图片本身已经先经过整图 mask，所以回拼后的图：
  - 只保留 mask 后的真实图像
  - 其他区域仍然是被 mask 的
- 同时把 `target_lines` 反投回全局坐标，输出：
  - `Lane.geojson`
  - `IntersectionBoundary.geojson`

### 5.1 验证脚本启动命令

```powershell
python scripts/reconstruct_geo_current_from_processed_dataset.py `
  --processed-root "D:\output\processed" `
  --output-root "D:\output\verify_train" `
  --split train `
  --stage stage_a
```

### 5.2 只验证某一个原始 sample

```powershell
python scripts/reconstruct_geo_current_from_processed_dataset.py `
  --processed-root "D:\output\processed" `
  --output-root "D:\output\verify_one" `
  --split train `
  --stage stage_a `
  --source-sample-id "你的sample_id"
```

### 5.3 输出结果

脚本会输出到：

- `输出目录\sample_id\masked_reconstructed.tif`
- `输出目录\sample_id\Lane.geojson`
- `输出目录\sample_id\IntersectionBoundary.geojson`
- `输出目录\reconstruct_summary.json`

## 6. 这个验证脚本用来检查什么

主要检查两件事：

1. **图像是否裁对**
   - patch 回拼后是否与 mask 后原图一致
   - patch 的位置是否和 `crop_box` 一致

2. **真值是否裁对**
   - `target_lines` 反投回全局后是否落在正确位置
   - 道路和路口边界是否符合 patch 导出的结果

如果这两件都对，说明当前数据集制作链基本正确。
