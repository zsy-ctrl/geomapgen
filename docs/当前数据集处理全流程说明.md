# 当前数据集处理全流程说明

本文按**当前仓库里正在使用的代码**说明 `geo_current_v1` 这条数据处理链，从原始数据集到训练数据、再到验证重建的全流程。

说明范围主要覆盖这几个文件：

- `scripts/build_geo_current_family_manifest.py`
- `scripts/export_llamafactory_both_from_geo_current_family_manifest.py`
- `scripts/reconstruct_geo_current_from_processed_dataset.py`
- `scripts/geo_current_dataset_v1_common.py`
- 以及当前链条复用的两个旧 helper 文件：
  - `scripts/export_llamafactory_patch_only_from_raw_family_manifest.py`
  - `scripts/export_llamafactory_state_sft_from_raw_family_manifest.py`

---

### 1.2 一次性导出 A/B 两阶段训练数据

主入口：

### 1.3 从处理后的训练数据重建 GeoTIFF / GeoJSON 做验证

### 4.2 `build_manifest_for_dataset()` 内部流程

调用函数：

#### 4.2.7 组装 patch 列表

- 第 1469-1501 行

### 6.2 `build_owned_segments_by_patch()` 做什么
函数位置：
- 第 1610 行

逻辑：
- 遍历 family 里的每个 patch
- 用 patch 的 `keep_box` 作为 `rect_global`
- 对该 patch 调 `build_patch_segments_global(...)`

也就是说：
- `crop_box` 决定图像输入范围
- `keep_box` 决定 GT 归属范围

### 6.3 `build_patch_segments_global()` 是当前最核心的真值转换函数
函数位置：
- 第 1227 行

它负责把：
- 全局 line / polygon GT

变成：
- 当前 patch 拥有的全局片段 `points_global`

#### 6.3.1 polygon 路径
关键代码：
- 第 1234-1253 行

调用函数：
- `ensure_closed_ring()`：第 1074 行
- `clip_polygon_ring_to_rect()`：第 1166 行

当前 polygon 路径做的事：
- 对 polygon 外环做矩形裁切
- 保持闭环
- 不走吸附
- 不走 mask 裁断

#### 6.3.2 line 路径
关键代码：
- 第 1255-1288 行

调用函数：
- `clip_polyline_to_rect()`：旧 helper，第 178 行，文件 `export_llamafactory_patch_only_from_raw_family_manifest.py`
- `_line_piece_cut_flags_after_clip()`：第 1040 行
- `resample_polyline_preserve_remainder()`：第 392 行
- `point_boundary_side()`：旧 helper，第 210 行
- `canonicalize_line_direction()`：旧 helper，第 231 行

当前 line 路径做的事：
- 先按 patch 的 `keep_box` 裁切
- 再判定 cut 端点
- 再按 `resample_step_px` 重采样
- 再做方向规范化

#### 6.3.3 当前允许修改 GT 的唯一几何步骤
当前主链里，几何允许被改的主要是：
- `resample_polyline_preserve_remainder()`：第 392 行

当前实现规则：
- 保留所有原始顶点
- 只在每一段内部按固定步长补点
- 最后一小段不足一个完整步长时，保留剩余长度
- 不再整条线重新均匀分布采样点

#### 6.3.4 当前不再走主链的“修补式”函数
这些函数仍然存在于文件里，但当前主链 **不调用**：

- `enforce_line_and_polygon_topology()`：第 571 行
- `clip_line_outside_polygons()`：第 726 行
- `snap_line_endpoints_to_polygon_boundaries()`：第 785 行
- `mask_clip_line()`：第 972 行
- `simplify_polyline_straight()`：第 1110 行

保留它们只是为了历史兼容/调试，不是当前训练真值主路径的一部分。

## 7. 第四步：把 patch 拥有的全局片段转成 patch-local 真值

在导出脚本里，这一步发生在：
- `scripts/export_llamafactory_both_from_geo_current_family_manifest.py` 第 123-128 行

### 7.1 训练主用：`build_patch_target_lines()`
函数位置：
- 第 1340 行

逻辑：
- 用 `crop_box` 的左上角作为 offset
- 做全局 -> patch-local 坐标转换
- 用 `clamp_points_float()`：第 382 行 做范围约束
- line 保持至少 2 点
- polygon 保持闭环

输出：
- `target_lines`
- **当前是浮点 patch-local UV 坐标**
- UV 定义是：
  - `u = x / patch_width`
  - `v = y / patch_height`
  - 取值范围 `[0, 1]`

### 7.2 可视化对照：`build_patch_target_lines_quantized()`
函数位置：
- 第 1309 行

逻辑：
- 把 patch-local 点再走旧的整数化流程

内部调用：
- `simplify_for_json()`：旧 helper，第 104 行

输出：
- `target_lines_quantized`
- **只给验证可视化用，不是当前主训练真值**

### 7.3 像素浮点对照：`build_patch_target_lines_float()`
函数位置：
- 第 1367 行

当前实现：
- 生成浮点 patch-local 像素坐标
- 主要给：
  - 验证 GeoJSON 回写
  - overlay 可视化
  - 与 UV 训练坐标做对照

## 11. 当前链条里“保真”相关的关键结论

### 11.1 当前主链中 mask 的作用
当前主链里：
- mask 用于：
  - 图像置黑：`load_family_raster_and_mask()` 第 1569-1576 行
  - 搜索 patch 区域：`build_manifest_for_dataset()` 第 1432-1440 行
  - 统计 `mask_ratio / mask_pixels`：第 1450 行

当前主链里：

## 坐标口径修正

当前 `geo_current` 处理链中的 `UV` 坐标系，统一指：

- patch 左上角为原点
- `u` 向右，`v` 向下
- 一个像素等于一个单位
- `target_lines` / `state_lines` 存储为 patch-local 整数坐标
- `target_lines_float` / `state_lines_float` 仅用于验证、回投和可视化

因此当前实现中，训练主数据 **不再** 使用 `[0,1]` 归一化 UV。
